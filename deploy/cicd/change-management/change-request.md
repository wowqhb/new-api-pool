# 变更申请模板

> 所有生产变更都要先填这份；紧急 hotfix 事后补。

## 基本信息

- **变更编号**：CR-YYYYMMDD-NNN
- **申请人**：@xxx
- **审批人**：@yyy（必须 ≥ 1，价格/限速变更 ≥ 2）
- **计划时间**：YYYY-MM-DD HH:MM (UTC+8)
- **预计耗时**：XX 分钟
- **风险等级**：低 / 中 / 高（决定审批人数与值班级别）

## 变更内容

### 是什么
（一句话说清楚）

### 为什么
- 业务背景：…
- 不做的后果：…

### 改了什么
- [ ] 代码（PR：…）
- [ ] 配置（diff：…）
- [ ] DB schema（migration：…）
- [ ] 基础设施（Ansible playbook：…）
- [ ] 第三方（Cloudflare / Vault / DNS：…）

### 涉及组件
- 网关 / DB / Redis / Sidecar / 监控 / 上游流水线 / …

## 风险评估

### 影响面
- 受影响用户：全部 / 付费 / 免费 / 单一渠道 …
- 受影响功能：…
- 是否影响计费：是 / 否
- 是否影响数据：是 / 否

### 备份与回滚

- [ ] 已备份：…（位置）
- [ ] 回滚方案：…（具体命令 / playbook）
- [ ] 回滚预计耗时：XX 分钟
- [ ] 已演练：是 / 否（staging）

### 验证清单

- [ ] CI 全绿
- [ ] staging 已部署 ≥ 24h
- [ ] 回归测试通过
- [ ] k6 压测通过
- [ ] 客服已知会
- [ ] 用户公告已发（如需）

## 实施步骤

1. T-30 min：通知值班 + 监控加哨兵
2. T-10 min：摘流（如需）
3. T+0：执行 `<具体命令>`
4. T+5 min：验证（具体怎么验）
5. T+15 min：恢复全流量（如有摘流）
6. T+30 min：观察 SLO，确认稳定

## 沟通

- [ ] 内部群通知（变更前 1h）
- [ ] 用户公告（变更前 24h，如需）
- [ ] 状态页（变更期间标记 maintenance）
- [ ] 完成后通报
