# Runbook 06：支付通道停服

**P1** · 影响：充值受阻，存量用户用余额仍能用 · 目标 MTTR：60 分钟内切到备用通道

## 现象 / 触发

- 充值成功率从 95% 跌到 < 50%
- 用户反馈 "扫码后没到账"
- 通道商发公告 / 跑路

## 前置准备

- [ ] **至少 2 个支付通道**（如 Stripe + 易支付，或 易支付 + USDT）
- [ ] 通道商联系方式存好（电报/QQ）
- [ ] 余额提现规则清楚（很多通道有 T+1/T+7 提现，跑路风险）
- [ ] 大额收款不要堆在通道账户，每天提

## 应急流程

1. **快速判断是通道故障还是配置错**：
   ```bash
   # 看充值订单状态分布
   docker exec new-api-postgres psql -U newapi -d newapi -c "
     SELECT status, count(*) FROM topup
     WHERE created_at > NOW() - INTERVAL '1 hour'
     GROUP BY status;
   "
   ```
   如果 `pending` 暴增 → 通道异步回调没回来 → 通道挂了。

2. **暂停问题通道**：
   - 管理后台 → 系统设置 → 支付设置 → 关掉问题通道
   - 或直接改 .env / DB 关闭

3. **启用备用通道**：
   - 改提示语："支付宝维护中，请用 USDT/Stripe"
   - 状态页公告

4. **追单**：
   - 看是否有 `pending` 订单已扣款没到账，联系通道商对账
   - 必要时人工补充值

## 通道商跑路（最坏情况）

- 立即停掉该通道，下架支付方式
- 余额能提多少提多少
- 联系所有最近 7 天充值但未到账的用户解释
- 走法律 / 报警（看金额）
