# 灰度发布 SOP（4 阶段）

## 阶段 1：内测（P1）

**时长**：1 周
**用户数**：5 人（创始团队 + 极少数信任的 dev 朋友）
**目标**：找出最低级 bug；验证基础流程

### 准入
- [ ] 上线前 checklist 100% 勾完
- [ ] 邀请码已下发
- [ ] 内测群（Telegram / 微信）建好

### 期间观察项
- 注册成功率 ≥ 95%
- 充值成功率 100%（5 个人都能充）
- API 调用成功率 ≥ 99%
- 没有 P0 / P1 事故
- 无投诉

### 工作内容
- 每天看一次告警
- 每天看一次 Grafana 总览
- 收集 5 个用户口头反馈
- 每周一次内测复盘会

### 晋级到 P2 的条件（all of）
- [ ] 一周无 P0 事故
- [ ] P1 事故 ≤ 1 个，已修复
- [ ] 5 个用户都成功跑通至少 100 次 API 调用
- [ ] 计费对账无误差
- [ ] 监控告警没乱响
- [ ] 团队达成 Go 共识

### 回滚（回到 build 阶段）的条件（any of）
- 发现影响所有用户的 P0
- 计费严重错误（多收 / 少收）
- 数据泄漏 / 安全事件
- 上游集体封号（说明流水线出问题）

## 阶段 2：白名单（P2）

**时长**：2 周
**用户数**：50 人（候补名单 / 收 form 筛选）
**目标**：验证扩展性与运营 SOP

### 准入
- [ ] P1 全部条件达标
- [ ] 客服话术 / 工单流程跑通过 ≥ 3 单
- [ ] 性能基线已建（k6 1k QPS 没问题）
- [ ] 容量评估：50 人最高峰能扛
- [ ] 上线公告 + 用户邮件准备好

### 期间观察项
- 客服工单平均响应时间 ≤ 4h
- 客服一次解决率 ≥ 60%
- 退款率 < 5%
- DAU / MAU > 50%（说明用户是真用，不是注册一次就跑）
- 渠道健康：3 类号池都正常运转

### 工作内容
- 每天看一次客服工单
- 每周看一次 BI 周报（GMV / 留存 / 异常）
- 每周一次复盘会（团队 + 客服）
- 客户访谈 ≥ 3 个（深度反馈）

### 晋级到 P3 的条件（all of）
- [ ] 两周内 P0 = 0、P1 ≤ 2 且已修
- [ ] 50 人中至少 30 人**真实付费**（不是赠送）
- [ ] 毛利率 ≥ 30%
- [ ] NPS ≥ 30 / CSAT ≥ 4.0（采访得到）
- [ ] 至少 1 个用户做了**回购**
- [ ] 客服月预算 / 工单数比例可控

### 回滚条件（any of）
- 单周 P1 ≥ 3 个
- 充值跑路 / 退款风波
- 上游 ToS 违规警告（来邮）
- 某分组渠道集体死亡 ≥ 24h
- DAU 持续下滑 > 20%

## 阶段 3：邀请码（P3）

**时长**：4 周
**用户数**：500 人（公开邀请码池子，老用户带新）
**目标**：验证规模化能力 + 运营自动化

### 准入
- [ ] P2 全部条件达标
- [ ] 邀请码裂变机制设计好（成功带 1 个返 X 额度）
- [ ] 客服扩容（兼职 / 外包 1 人，或 AI 客服）
- [ ] 自动化运维成熟（变更不再手工）

### 期间观察项
- p95 延迟稳定（不能比 P2 慢）
- 错误率 < 1%
- 号池容量自动维持（流水线在跑）
- 异常用户告警准确率（误杀 < 5%）
- 退款率 < 3%
- 缓存命中率 ≥ 10%

### 工作内容
- 每天 BI 早报推送
- 每周复盘会
- 月度 SLA 报告
- 月度财务对账
- 上游成本优化（缓存 / 阶梯）

### 晋级到 P4 的条件（all of）
- [ ] 一个月内无 P0
- [ ] P1 ≤ 3 个，月内全部修复
- [ ] 月 GMV ≥ $X（自定）
- [ ] 月毛利率 ≥ 35%
- [ ] 周活留存 ≥ 40%
- [ ] 客服一次解决率 ≥ 70%
- [ ] 单 SRE 能扛（不再加班）

### 回滚条件（any of）
- 月 P0 ≥ 1
- 月毛利亏损 ≥ $500
- 上游账号大批失效 > 30%
- 重大法律 / 合规问题

## 阶段 4：公开（P4）

**时长**：永远（）
**目标**：稳定运营 + 增长

### 准入
- [ ] P3 全部达标
- [ ] 增长策略已定（SEO / Reddit / Twitter / 投放）
- [ ] 法务对外宣传文案 review 过
- [ ] 多区域部署完成

### 持续运营节奏
- **每天**：早报推送、客服值班、告警响应
- **每周**：周报、复盘、变更回顾
- **每月**：SLA 报告、财务对账、容量规划、密钥轮换检查
- **每季度**：密钥轮换、法务文档复审、灾备演练
- **每半年**：架构 review、技术债清理、价格策略调整

### 重大事件触发降级
- 触发 P0 事故 ≥ 1 → 暂时关闭新注册（≥ 24h）
- 上游突发涨价 / 限制 → 紧急调价
- 法律风险升级 → 法务介入 + 评估是否暂停某区域

## 公共：每阶段必须的"开关"

无论哪个阶段，这些"急停按钮"必须随时可用：

```bash
# 1. 关闭新注册
deploy/scripts/disable-registration.sh

# 2. 暂停某分组所有渠道
deploy/scripts/group-disable.sh --group official

# 3. 全域只读模式（应对故障）
deploy/scripts/readonly-mode.sh on

# 4. 一键回滚部署
deploy/cicd/scripts/rollback.sh

# 5. 切到备用 DNS / 备用域名
deploy/multi-region/scripts/dns-direct.sh
```

每个上面的脚本，**必须演练 ≥ 1 次**，写文档时写清楚副作用。
