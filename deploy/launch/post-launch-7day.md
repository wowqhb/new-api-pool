# 上线后 7 天巡检

> 每个阶段开始的前 7 天最关键，按这里的清单每日逐项过。

## Day 1：开闸日

**值班强度**：12-24 小时全员盯
**重点**：第一波用户体验

### 早 9 点
- [ ] 总览仪表板：RPS / 错误率 / p95
- [ ] 上游各渠道健康
- [ ] 工单系统：累计工单 / 未读 / 紧急
- [ ] 充值：累计 / 失败 / 平均额度
- [ ] 看 Telegram 用户群有没有抱怨

### 中午 12 点
- 同上
- 累计 vs 预期（注册 / 调用 / GMV）

### 下午 6 点
- 同上
- 当日 P0/P1 事件汇总
- 发用户公告（如有调整）

### 晚 11 点
- 当日总结写入复盘文档
- 第二天值班接班

### 必须解决（不解决不算 Day 1 收尾）
- [ ] 所有 P0 事件已 closed
- [ ] 所有用户工单（紧急）已响应
- [ ] 监控告警没有未读
- [ ] 当日数据库备份成功

## Day 2-3：稳定期

**值班强度**：8 小时主班 + on-call

### 每日早 9 点早会（15 分钟）
- 昨日 DAU / GMV / 退款 / P0 / P1
- 今日重点（修复哪个 bug、发哪个 feature）
- 风险预警

### 关注重点
- 新发现的 bug 数量
- 第二天用户留存率（昨日注册的，今日还活跃 %）
- 客服一次解决率
- 缓存命中率（开始稳定）

### 典型动作
- 修 P2-P3 bug
- 优化告警规则（减少误报）
- 调整客服话术（基于第一天的工单）

## Day 4-5：调优期

### 关注重点
- 性能：是否有慢查询、热点
- 成本：上游成本 vs 营收，毛利率走势
- 异常用户：被告警的用户是否真异常

### 典型动作
- 调整渠道权重（哪些表现好升 weight）
- 调整模型倍率（如果亏损）
- 优化数据库索引（基于慢查询）
- 缓存策略调整（哪些命中低的开 L1）

## Day 6：复盘准备

- [ ] 写 7 天总结（数据 + 经验 + 教训）
- [ ] 列下周改进项
- [ ] 准备下周 Go/No-Go 决策

## Day 7：周复盘 + 决策

### 周复盘会议（≥ 30 分钟，全员）

议程：
1. 数据回顾（5 min）：DAU / GMV / 错误 / 客服
2. 重大事件回顾（10 min）：P0 / P1 / RCA
3. 用户反馈（10 min）：好评 / 差评 / 需求
4. 改进项确认（5 min）

### 决策
- 数据达标 → 维持当前阶段，进入第二周
- 数据小偏 → 修复后继续观察
- 数据严重偏 → 评估是否回滚

## 7 天数据基线（参考值）

> 不同阶段不同基线。下面是 P3（500 人邀请码）的参考。

| 指标 | Day 1 | Day 3 | Day 7 |
|---|---|---|---|
| 累计注册 | 100 | 250 | 500 |
| 累计付费 | 5 | 30 | 80 |
| 累计 GMV | $50 | $300 | $1,200 |
| DAU | 80 | 200 | 350 |
| API 调用/日 | 5K | 30K | 100K |
| 工单数 | 20 | 30 | 50 |
| P0 数 | 0 | 0 | 0 |
| P1 数 | ≤ 1 | ≤ 2 | ≤ 3 |
| 退款率 | < 10% | < 8% | < 5% |
| 错误率 | < 2% | < 1% | < 1% |

## 红线（任一触发立即暂停）

- 累计 P0 ≥ 1
- 单日错误率 > 5% 持续 1 小时
- 单日退款 ≥ 20%
- 上游账号封禁批量 ≥ 30%
- 资金被冻结 / 银行预警
- 法律警告函

触发后：暂停新注册 → 召集 war room → 写紧急公告。

## 7 天后的下一步

- 进入第二周稳定运营
- 月底做月度复盘
- 准备下一阶段晋级评估
